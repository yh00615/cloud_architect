## 3. CloudShell에서 AssumeRole 실행 및 S3 접근 테스트 (4분)

### 화면 전환

- AWS CloudShell 실행

### 멘트

"AWS 관리 콘솔에서 왼쪽 하단 부분의 CloudShell을 실행합니다."

**[클릭: CloudShell 아이콘]**

**[대기: CloudShell 로딩]**

"먼저 현재 자격증명을 확인해보겠습니다."

**[입력 및 실행]**

```bash
aws sts get-caller-identity
```

**[화면: 출력 결과]**

"Arn을 보시면 `lab-user`로 표시되는 것을 보실 수 있습니다. 현재 IAM 사용자로 인증되어 있습니다."

"이것이 역할 전환 전의 상태입니다. 이제 S3 버킷 목록을 조회해보겠습니다."

**[입력 및 실행]**

```bash
aws s3 ls
```

**[화면: AccessDenied 오류]**

"예상대로 AccessDenied 오류가 발생합니다. 현재 사용자는 S3 접근 권한이 없기 때문입니다."

"이제 AssumeRole을 사용해서 S3ReadOnlyRole 역할을 맡아보겠습니다."

**[입력 및 실행]**

```bash
aws sts assume-role \
  --role-arn arn:aws:iam::123456789012:role/S3ReadOnlyRole \
  --role-session-name s3-readonly-session
```

**[화면: 출력 결과 - Credentials 섹션]**

"AssumeRole이 성공하면 이렇게 임시 자격증명을 받습니다."

"Credentials 섹션을 보시면 AccessKeyId, SecretAccessKey, SessionToken 세 가지 값이 있습니다."

"이 값들을 환경 변수로 설정하면 AWS CLI가, 이 임시 자격증명을 사용하게 됩니다."

**[화면: 메모장에 미리 준비한 export 명령어 3줄]**

"실습에서는 이 세 값을 복사해서 환경 변수로 설정해야 합니다. 저는 미리 준비해둔 명령어를 사용하겠습니다."

## 4. 역할 전환 전후 비교표 정리 및 마무리 (3분)

### 화면 전환

- 실습 가이드의 비교표 섹션으로 이동

### 멘트

"이제 방금 확인한 내용을 표로 정리해보겠습니다."

**[화면: 비교표]**

"역할 전환 전후를 비교해보면 차이점이 있습니다."

**[표의 첫 번째 행 - 로그인 신분을 가리키며]**

"첫째, 로그인 신분입니다. 처음에는 lab-user였지만, AssumeRole 후에는 assumed-role로 바뀌었습니다."

**[표의 두 번째 행 - 연결된 정책을 가리키며]**

"둘째, 연결된 정책입니다. lab-user는 IAM 읽기, CloudShell, AssumeRole 권한만 있었지만, 역할을 맡은 후에는 S3 읽기 정책을 사용하게 됩니다."

**[표의 세 번째 행 - aws s3 ls 명령어 결과를 가리키며]**

"셋째, AWS CLI로 S3 버킷 목록 조회입니다. 처음에는 AccessDenied 오류가 발생했지만, 역할을 맡은 후에는 성공했습니다."

**[표의 네 번째 행 - 자격 증명을 가리키며]**

"넷째, 자격 증명입니다. 처음에는 장기 자격증명을 사용했지만, AssumeRole 후에는 임시 자격증명을 사용합니다. 기본 1시간 동안 유효합니다."

"자격증명 우선순위에 대한 자세한 내용은 실습 가이드의 참고 사항을 보시면 됩니다."

**[표의 다섯 번째 행 - 인증 수단을 가리키며]**

"다섯째, 인증 수단입니다. 처음에는 고정된 Access Key를 사용했지만, 역할을 맡은 후에는 임시 Access Key와 Session Token을 함께 사용합니다."

**[표의 여섯 번째 행 - 비유를 가리키며]**

"마지막으로, 비유하자면 처음에는 사원증을 직접 들고 있는 상태였고, 역할을 맡은 후에는 특정 구역 전용 출입증을 받은 상태입니다."

"이렇게 AssumeRole을 사용하면 필요한 시점에만 권한을 얻을 수 있어서 보안이 강화됩니다."

### 실무 활용 사례

"실무에서는 Lambda 함수가 실행될 때 자동으로 역할을 맡아서 필요한 권한을 얻거나, 다른 AWS 계정의 리소스에 접근할 때 Cross-Account Access로 사용합니다."

"실습 가이드에는 더 자세한 단계와 설명이 있으니 직접 따라해보시기 바랍니다."

## 📝 준비 사항

### 사전 준비

1. AWS 계정에 Week 2-2 실습 환경 구축 (CloudFormation 스택 배포)
2. IAM 사용자에 `AssumeS3ReadOnlyRolePolicy` 인라인 정책 추가
3. S3ReadOnlyRole 역할 생성 및 ARN 복사
4. 메모장에 export 명령어 3줄 미리 작성 (실제 자격증명 값 포함)

### 화면 전환 순서

1. 실습 가이드 웹페이지
2. IAM 콘솔 (Users → Permissions)
3. CloudShell
4. 실습 가이드 웹페이지 (비교표)

### 주의 사항

- CloudShell 로딩 시간 고려 (미리 열어두기)
- AssumeRole 명령어의 역할 ARN은 실제 계정 ID로 교체
- 임시 자격증명 값은 보안상 촬영 후 즉시 만료시키기
- 시연 후 리소스 정리 (CloudFormation 스택 삭제)
